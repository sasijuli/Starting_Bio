# Reproducibility And Data Management

## Purpose

Keep simulations organized so another researcher can understand, repeat, and audit the workflow.

## Planned Topics

- Directory structure for inputs, configurations, logs, restarts, and analysis
- File naming and stage numbering
- Recording NAMD and force-field versions
- Preserving original inputs
- Random seeds and nondeterminism
- Checksums and data integrity
- Git for scripts and configuration files
- Storage policies for large trajectories
- Simulation manifests and run notes

## Suggested Outcome

Create a run manifest that records the inputs, configuration, software version, command, computing environment, and outputs for every simulation stage.
